**根本原因**: An out-of-bounds write from the mpt3sas driver (shared kmalloc-128 slab) overwrote an irqaction structure for IRQ 863, corrupting its 'next' pointer to 0x800c00000010. When show_interrupts iterated the irqaction chain to read the name of the next action, it dereferenced 0x50(%rbp) using this corrupted pointer, causing a page fault.

The crash occurred when irqbalance read /proc/interrupts, triggering show_interrupts (kernel/irq/proc.c). The faulting instruction mov 0x50(%rbp),%rdx attempted to load the 'name' field (offset 0x50) from the irqaction pointed to by RBP. This code matched the 'originator(IOP), code(0x03), sub_code(0x0109)' messages flooding dmesg immediately before the crash.
